# Project instructions

## Project name

- Use `Actual Budget Importer` as the displayed application name.
- Use `actual-budget-importer` for the repository, package, and
  container image name.

## Approval process

- Choose the simplest reasonable design and implementation that
  satisfies the current approved task. Do not ask for approval for
  ordinary technical choices made within that scope.
- Seek explicit approval before expanding the task's scope, changing
  the product specification or technical design, or taking a material
  external or destructive action.
- Every addition or edit to this file requires approval.
- Read-only inspection may be used to prepare proposals.
- Treat changes to the product specification or technical
  design as project changes governed by this approval process.

## Git workflow

- Codex may commit and push approved changes directly to `main`.

## Code comments

- Keep code comments only when they provide necessary context that
  the code itself cannot clearly express.

## Required specifications

- Read `docs/product-spec.md` and `docs/technical-design.md`
  before proposing or implementing project changes.
- Treat both documents as authoritative requirements.
- Keep each requirement in one authoritative location rather
  than duplicating it across these files.

## Public repository

- Keep credentials, real statements, and personal financial
  data out of version control.
- Use synthetic data in committed examples.
- Make installation-specific settings configurable rather
  than hardcoding the owner's setup.
- Document setup and configuration so other people can
  run the app.
- The owner must approve the license before one is added.
